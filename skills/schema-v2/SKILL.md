# Schema v2 — Super Model + Datapoint Provider

## Core Concept

Every model has a **super model** (abstract identity) and one or more **datapoints** (provider-specific instances). The same model (e.g. "GLM-4.7") offered by OpenRouter, NVIDIA, Cerebras, etc. is one super model with many datapoints.

## Tables

| Table | Purpose | Key Fields |
|---|---|---|
| `super_models` | Abstract model identity | `id`, `name`, `slug` (normalized) |
| `datapoint_providers` | Data source providers | `id`, `slug`, `name`, `base_url` |
| `datapoint_models` | One row per provider instance | `super_model_id`, `datapoint_provider_id`, `remote_id`, `full_id`, all model fields, status_*, `is_removed` |
| `datapoint_model_input_types` | Input types per instance | `datapoint_model_id`, `input_type` |
| `datapoint_model_output_types` | Output types per instance | `datapoint_model_id`, `output_type` |
| `datapoint_model_features` | Tags/best_for per instance | `datapoint_model_id`, `feature_type`, `value` |
| `test_results` | Test history | `datapoint_model_id`, `tested_at`, `result`, `detail` |
| `metadata` | Key-value store (rankings, etc.) | `key`, `value` (JSONB) |

## Key Design Decisions

- **`full_id`** = `providerSlug/remoteId` (e.g. `openrouter/owl-alpha`). Unique across all datapoints.
- **`source`** in API/export = provider slug (e.g. `openrouter`, `nvidia`). Not a separate enum.
- **`is_removed`** on datapoint_models (boolean) — provider no longer lists this model.
- **Status fields** (`status_result`, `status_tested`, `status_detail`, `last_success`) are per-datapoint, not per-super.
- **Features** (best_for, tags) are per-datapoint, not per-super.

## Normalization

Super model slugs are generated by `normalize_model_slug()`:
- Lowercase
- Strip prefixes: `coding-`, `xiaomi-`
- Strip suffixes: `(free)`, `(free tier)`
- Replace special chars with hyphens
- Collapse multiple hyphens

## Migration

- **v1→v2**: `scripts/migrate-v1-to-v2.js` — migrates old `models`/`provider_models`/`modelsdev` into new tables. Idempotent (TRUNCATES new tables first).
- **Schema DDL**: `db/schema.sql` — uses `CREATE TABLE IF NOT EXISTS` pattern. Safe to re-run.

## Gotchas

- **Old tables still exist** (`models`, `provider_models`, etc.) — not dropped after migration. Drop manually after verification.
- **`datapoint_providers` seeded from both schema.sql AND old `providers` table** during migration. Total: 60 providers.
- **`notes` field** is null for all migrated data — was never populated in v1.
- **`_removedDate`** is null — was on old `models` table, not migrated. Use `is_removed` + metadata instead.
- **JQL `source:` filter** now matches provider slugs (`source:openrouter`), not old values (`source:curated`).

## models.dev as Canonical Source

models.dev is the **authoritative source** for which models exist. Every `super_models` row should have at least one `datapoint_models` row from the `modelsdev` provider.

- **Provider ID**: `modelsdev` in `datapoint_providers`
- **Import script**: `node scripts/import-modelsdev.js [--apply]`
- **Backfill script**: `node scripts/import-modelsdev-backfill.js [--apply]` — matches remaining supers by normalizing remote_ids (dots↔hyphens, stripping prefixes/suffixes)
- **Synthetic entries**: Models not found in models.dev get a synthetic `modelsdev/{slug}-master` datapoint. These exist because the model is free on some provider API but not listed on models.dev.
- **Why this matters**: The import ensures every super has a "ground truth" reference point. When a model disappears from all providers including models.dev, it's a strong signal to deprecate.

## Duplicate Merging

When the same model gets multiple `super_models` rows (due to naming differences across providers):

1. Normalize slugs: `UPDATE super_models SET slug = normalize_model_slug(name)`
2. **Drop the unique constraint first**: `ALTER TABLE super_models DROP CONSTRAINT super_models_slug_key` (named `master_models_slug_key` from pre-migration)
3. Reassign datapoints: move all `datapoint_models` from duplicates to the super with most datapoints (lowest ID wins ties)
4. Delete duplicate supers and orphaned datapoints
5. Re-add constraint: `ALTER TABLE super_models ADD CONSTRAINT super_models_slug_key UNIQUE (slug)`
6. Full script: `db/merge-super-duplicates.sql`

**Key insight**: Postgres checks unique constraints per-row during UPDATE, not at end of statement. You MUST drop the constraint before normalizing slugs, or you get `duplicate key value violates unique constraint`.

## Synthetic modelsdev Remote IDs

When a `super_models` row can't be matched to any modelsdev entry, the backfill creates a synthetic datapoint with `remote_id = {slug}-master`. This avoids colliding with real modelsdev remote_ids. If you need to distinguish real vs synthetic: real ones exist in `modelsdev-free-models.json`, synthetic ones have the `-master` suffix.
